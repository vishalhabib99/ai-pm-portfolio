# Pre-registration: fresh-set check of the gap-abstain rule and the retry step

Written 2026-09-28, **before** the fresh tickets exist. Committed before the run so the criteria can't move.

## Why

The 0.02 top-2 gap threshold was chosen by looking at `tickets_eval.json`, so its 60% → 80% gain is in-sample. The retry step added nothing on that set. This checks both on tickets nobody tuned against.

## Fresh set

- `tickets_fresh.json`, written by a separate agent that sees only `docs/` and the category list: no code, no scores, no README, no original tickets.
- Target: 12 in-scope (3 per category) + 4 off-topic. Used once. It's not added to the tuning set afterwards.

## Frozen

- `CONFIDENCE_THRESHOLD = 0.08`, `GAP_THRESHOLD = 0.02`, stemmer as in commit b9e2137. No code or threshold changes after seeing the fresh results.

## Pass criteria

- **H1, gap-abstain holds:** "+ abstain on narrow gap" has higher precision-when-answering than the baseline **and** loses at most 1 in-scope ticket that the baseline got right.
- **H2, retry earns its place:** "+ retry, then abstain" gets at least 1 ticket right that "+ abstain on narrow gap" got wrong. Prediction: fails (it added nothing in-sample).

Any other result is reported as-is, in the README.

## Result (run 2026-09-28, once, no code or threshold changes)

16 fresh tickets from a separate agent that saw only `docs/`.

```
config                         accuracy   precision when answering  retried
baseline (score only)        38% (6/16)                 38% (6/16)        0
+ abstain on narrow gap      38% (6/16)                 40% (6/15)        0
+ retry, then abstain        44% (7/16)                 44% (7/16)        1
Recall@1: 50% (6/12)   Recall@2: 67% (8/12)
```

Exactly one ticket differs across the three configs: "where do I find old receipts?" (billing). The baseline picks `plan_limits` (gap 0.009). Abstain-only routes it to a human. The retry's stemmed pass picks `billing` (gap 0.026) and gets it right.

- **H1: passes as written, fails in substance.** Precision went from 38% to 40% by abstaining on one ticket the baseline already got wrong, and no in-scope answer was lost. But the rule caught **0 of 4** off-topic tickets. Their gaps were 0.021, 0.027, 0.038 and 0.062, all above 0.02, and all 4 got confident wrong drafts. In-sample it caught 2 of 2. The criterion was too weak: "any precision gain" let a one-ticket change count as a pass. The rule does not do what it was built for.
- **H2: passes, against the prediction.** The retry turned one abstention into a correct answer ("receipts" → "Receipts"/billing after suffix-stripping). That's n = 1, but it's a real case of the mechanism working: the first pass was ambiguous, and the rewrite added a word match that was missing.
- **The bigger finding:** the baseline dropped from 60% (original set) to 38% on fresh tickets, and Recall@1 from 75% to 50%. Retrieval is the main problem, and the original 10 tickets were easier than real phrasing ("Too Many Requests" for 429, "spinning wheel" for a bug, "Microsoft sign-in" for SSO).
